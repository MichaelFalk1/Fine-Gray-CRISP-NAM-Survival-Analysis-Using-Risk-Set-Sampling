## Writing and citation preferences

- Use clear, direct MSc-level academic prose. Avoid inflated claims, vague motivation, unnecessary technical detail and promotional language.
- Existing research-question/objective lists should remain lists. New thesis explanations should be connected paragraphs, not new lists.
- Cite new literature-based claims using verified, relevant sources. Use `\citep{key}` at the end of the supported claim/sentence, before the final full stop. Use `\cite{key}` only within a sentence.
- Check that citation keys exist and that sources support the particular claim. Do not use a Cox/DeepHit citation as evidence of an implementation-specific Fine-Gray bottleneck.
- Experimental findings should point to this study's relevant results/figures/tables. Do not add literature citations as substitutes for empirical evidence.
- Do not promise statistical validity, unbiased loss, exact equivalence, universal superiority or guaranteed speed-ups without support.
- Do not equate lower Brier score with proof of calibration alone.
- Explain the computational motivation directly. The user disliked the event-by-observation matrix explanation in the introduction as unnecessary detail.
- Do not state that all survival algorithms necessarily have quadratic complexity. Distinguish the implementation, batch size and full cohort when needed.

## Implementation facts already inspected

These describe inspected active code, not an independent certification of correctness. Recheck relevant cells before changing mathematical text. Notebooks contain commented-out old code; do not mistake it for the active loss.

- Target-cause events define loss rows. Eligible observations are those with `T_j >= T_i`, plus prior competing events with `T_j < T_i` and event code neither 0 nor the target cause.
- Active observations have Fine-Gray weight 1. Prior competing-event observations have weight `G_hat(T_i-) / G_hat(T_j-)`. Previously censored and previous target events are excluded.
- Censoring Kaplan-Meier estimation uses the training fold, with censoring code 0; weights use left limits.
- Sampling contribution weights are `w_FG / pi_ij`; the current event case has inclusion probability 1.
- Active loss uses log-sum-exp and mean target-event contributions, with no extra outer event weight. Upper weight clipping is disabled; gradient clipping is separate.
- User clarified the ORIGINAL stabilisation motivation: avoid excessive variability in sampling-weighted loss contributions rather than relying on L2 parameter regularisation to address it. Preserve this motivation, but distinguish it from the CURRENT implementation, which uses plain inverse sampling probabilities, not marginal-probability-stabilised IPW. Do not describe the two weighting components as mathematically conflicting or claim log-sum-exp removes sampling variance.
- SCC draws a Bernoulli subcohort once per training fold and reuses membership across batches/epochs via stable observation IDs. Each risk-set row forces in its current event case, not all future cases. Other eligible subcohort observations have inclusion probability alpha.
- NCC samples up to m controls without replacement, excluding the current case, using inclusion probability `min(m, available) / available`.
- Entropy computes normalized binary entropy of sigmoid-transformed risk scores, temperature-scaled exponential scores, and independent Bernoulli selection with probabilities scaled relative to the eligible-control mean. Sigmoid scores are sampling heuristics, not calibrated CIF probabilities.
- FULL training means all eligible observations WITHIN each mini-batch, not necessarily the full training cohort.
- Baseline subdistribution hazard estimation uses full training-fold risk sets with Fine-Gray weights. Baseline cumulative hazard is evaluated as a step function.
- SCC validation uses unsampled mini-batch risk sets; inspected NCC/entropy validation still samples. Describe actual code, not an assumed common protocol.
- The corrected first `Loss Function` section is retained. The user confirmed commenting out the obsolete second section as a fallback. Preserve that fallback; do not present its deletion as outstanding work.
- PBC current notebook reads `RealWorldData/grouped_pbc.csv`. Verify preprocessing and fold units before asserting equivalence with old longitudinal/grouped analyses.
- Metrics code uses `EvalSurv` with target-cause binary event indicators. Do not certify its competing-risk metric interpretation without reviewing definitions.
